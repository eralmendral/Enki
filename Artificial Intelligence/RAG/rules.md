# Writing Rules for AI/Tech Notes

Guidelines for creating accessible technical documentation.

---

## Audience

Write for someone with **zero technical background**. If your grandma can't understand it, simplify further.

---

## Structure

1. **Title** – Clear topic name
2. **One-liner** – What is this in one sentence?
3. **Analogy** – Real-world comparison before any technical explanation
4. **Core concepts** – Bullet points or short sections
5. **Tables** – Use for comparisons (when X works vs. when it doesn't)
6. **Key takeaway** – End with a memorable summary quote

---

## Style Rules

| Do | Don't |
|----|-------|
| Use everyday analogies (library, kitchen, shopping) | Use jargon without explanation |
| Keep sentences under 20 words | Write long paragraphs |
| Use tables for comparisons | Bury comparisons in text |
| Bold key terms on first use | Assume prior knowledge |
| Use horizontal rules to separate sections | Wall of text |

---

## Analogies Bank

Use familiar concepts to explain technical ones:

| Technical Concept | Good Analogy |
|-------------------|--------------|
| RAG | Librarian helping you write a report |
| Keyword search | Ctrl+F on a document |
| Semantic search | A friend who "gets what you mean" |
| Vector embeddings | GPS coordinates for meaning |
| Chunking | Cutting a book into chapters |
| Indexing | Library card catalog |

---

## Template

```markdown
# Topic Name

One sentence explaining what this is.

## What is [Topic]?

**Analogy:** [Real-world comparison]

[2-3 sentences expanding on the analogy]

---

## [Core Concept 1]

[Explanation with examples]

### When It Works

| Scenario | Why |
|----------|-----|

### When It Doesn't

| Scenario | Why |
|----------|-----|

---

## Key Takeaway

> [Memorable one-liner summary]
```
